# 网页快照解析

状态：planned；未实现、未启用。建议优先级：P1。属于资料家族，后续可以是同一个进程中的模块，不要求独立服务。

## 范围

首批候选：`.html`、`.htm`。后续候选：`.mhtml`、`.mht`。这些是规划，不是支持声明。

## 专用流程

接收固定 HTML 快照 → DOM/正文提取 → 表格/资源关系 → 块与快照定位。

## 定位与输出

URL、快照摘要/采集时间、DOM 位置、资源引用。

现有 v0.1.0-draft.1 不一定能表达本家族全部结构，按 [结果模型](../../../../docs/result-model.md) 升级契约后再开放相应能力。

## 依赖边界

只依赖 core 定义的接口，apps 注入成熟转换/内容增强适配、非模型工具和外部 Provider；仅按当前家族需要使用。非模型工具分组：markup。按目标可能需要的外部能力：ocr、vision；不是每个文件都全部调用。不得导入其他家族内部代码；复合资料走 core 子任务分派。

## 复用候选

完整 HTML 结构优先复用已选 Docling backend；只有明确请求正文视图时按需使用 Trafilatura 的提取入口，不启用其下载/爬虫或全量 extras。保留原始快照与派生关系，清洗后的节点不能宣称仍有精确原始 DOM 定位。 具体边界见 [横向选型](../../../../docs/research/2026-10-15-module-selection.md) 和 [实现方案](../../../../docs/implementation-plan.md)；当前未安装或启用。

## 实现前验收

动态页面需先采集、正文清洗丢信息、图片延迟加载；解析器不私自抓取原 URL 或执行脚本。

共同规则见 [处理流程](../../../../docs/pipelines.md) 与 [评测计划](../../../../evals/README.md)。
