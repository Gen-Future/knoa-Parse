# 结构化数据解析

状态：部分实现；当前只启用 .json（UTF-8、拒绝重复键与非有限值），其他后缀未启用。建议优先级：P0。属于资料家族，后续可以是同一个进程中的模块，不要求独立服务。

## 范围

首批候选：`.json`、`.jsonl`、`.xml`、`.yaml`、`.yml`。暂不增加其他扩展。这些是规划，不是支持声明。

## 专用流程

成熟语法读取器 → 记录/节点树 → 类型与节点路径 → 结构化内容。

## 定位与输出

记录序号、JSON Pointer 或格式节点路径；有条件时保留原始跨度。

现有 v0.1.0-draft.1 不一定能表达本家族全部结构，按 [结果模型](../../../../docs/result-model.md) 升级契约后再开放相应能力。

## 依赖边界

只依赖 core 定义的接口，apps 注入成熟转换/内容增强适配、非模型工具和外部 Provider；仅按当前家族需要使用。非模型工具分组：markup。本家族自身默认不调用模型；子资料按其家族能力规划。不得导入其他家族内部代码；复合资料走 core 子任务分派。

## 复用候选

所选语言的 JSON/JSONL/XML/YAML 库，不自研语法解析器。依据与取舍见 [调研](../../../../docs/research/2026-10-14-parser-landscape.md)，尚未安装或锁定运行时依赖。

## 实现前验收

重复键、坏行、数值精度、深层结构、XML 实体和 YAML 对象构造限制；默认不调用模型。

共同规则见 [处理流程](../../../../docs/pipelines.md) 与 [评测计划](../../../../evals/README.md)。
