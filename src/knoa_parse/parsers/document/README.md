# Word 与流式文档解析

状态：初始原生路径已实现；需安装并通过 documents 组审计，后续格式和模型目标仍未启用。建议优先级：P0。属于资料家族，后续可以是同一个进程中的模块，不要求独立服务。

## 范围

首批候选：`.docx`。后续候选：`.doc`、`.odt`、`.rtf`。这些是规划，不是支持声明。

## 专用流程

文档容器/关系 → 段落/表格/图片/备注 → 子内容分派 → 可选渲染增强 → 原结构定位。

## 定位与输出

当前段落和表格定位到保留的上游树；不输出原 XML 节点 ID 或 Word 固有页码。关系 ID 与渲染定位属于后续能力。

当前输出 v0.2.0-draft.1，能力边界与后续升级见 [结果模型](../../../../docs/result-model.md)。多节页眉/页脚、脚注、插入修订文字及合并表格的合成验收见 [M2 覆盖](../../../../evals/m2-coverage.md)；不代表完整修订历史或任意 Word 特性。

## 依赖边界

只依赖 core 定义的接口，apps 注入成熟转换/内容增强适配、非模型工具和外部 Provider；仅按当前家族需要使用。非模型工具分组：office、markup。按目标可能需要的外部能力：ocr、vision、document_analysis；不是每个文件都全部调用。不得导入其他家族内部代码；复合资料走 core 子任务分派。

## 复用候选

优先复用 Docling 的 Word backend 与 SimplePipeline，保留完整文档结构再映射 Knoa 证据。python-docx 等作为上游基础依赖或已证明缺口的补充；旧格式和渲染另行评估。 依据见 [横向选型](../../../../docs/research/2026-10-15-module-selection.md) 与 [实现方案](../../../../docs/implementation-plan.md)，已在 Python 3.12 环境锁定并验证所选路径；不代表所有 Office 特性或复杂 PDF 均被完整恢复。

## 实现前验收

页眉页脚、文本框、脚注、修订、嵌入对象、字体变化；这些覆盖需逐项验证，不能默认全支持。

共同规则见 [处理流程](../../../../docs/pipelines.md) 与 [评测计划](../../../../evals/README.md)。
