# 邮件与邮件集解析

状态：planned；未实现、未启用。建议优先级：P2。属于资料家族，后续可以是同一个进程中的模块，不要求独立服务。

## 范围

首批候选：`.eml`、`.mbox`。后续候选：`.msg`。这些是规划，不是支持声明。

## 专用流程

消息/MIME 读取 → 头部/正文表示去重 → 附件子任务 → 邮件关系聚合。

## 定位与输出

消息 ID、邮件序号、MIME part、附件路径/摘要；正文与附件独立。

现有 v0.1.0-draft.1 不一定能表达本家族全部结构，按 [结果模型](../../../../docs/result-model.md) 升级契约后再开放相应能力。

## 依赖边界

只依赖 core 定义的接口，apps 注入成熟转换/内容增强适配、非模型工具和外部 Provider；仅按当前家族需要使用。非模型工具分组：markup、containers。本家族自身默认不调用模型；子资料按其家族能力规划。不得导入其他家族内部代码；复合资料走 core 子任务分派。

## 复用候选

语言 email/mailbox 库；MSG 候选 Tika 或专门读取器，独立验证。依据与取舍见 [调研](../../../../docs/research/2026-10-14-parser-landscape.md)，尚未安装或锁定运行时依赖。

## 实现前验收

HTML/文本双表示、编码头部、内联图片、嵌套邮件、恶意附件；附件的模型需求由对应家族声明。

共同规则见 [处理流程](../../../../docs/pipelines.md) 与 [评测计划](../../../../evals/README.md)。
