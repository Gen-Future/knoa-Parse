# PDF解析

状态：初始原生路径已实现；需安装并通过 documents 组审计，后续格式和模型目标仍未启用。建议优先级：P0。属于资料家族，后续可以是同一个进程中的模块，不要求独立服务。

## 范围

首批候选：`.pdf`。暂不增加其他扩展。这些是规划，不是支持声明。

## 专用流程

页级探测 → 原生文本/几何提取 → 必要页渲染 → 外部 OCR 或文档分析 → 结构与出处合并。

## 定位与输出

当前输出原始页码、点数区域和原生归因；阅读顺序 unresolved，不恢复表格。OCR 属于后续服务能力。

当前输出 v0.2.0-draft.1，见 [结果模型](../../../../docs/result-model.md)。含位图页面保守返回覆盖缺口和 partial，不因存在文字页眉而标记完整；含装饰图片也可能 partial。中文、多列、90 度旋转与混合页见 [M2 覆盖](../../../../evals/m2-coverage.md)。

## 依赖边界

只依赖 core 定义的接口，apps 注入成熟转换/内容增强适配、非模型工具和外部 Provider；仅按当前家族需要使用。非模型工具分组：pdf。按目标可能需要的外部能力：ocr、document_analysis、vision；不是每个文件都全部调用。不得导入其他家族内部代码；复合资料走 core 子任务分派。

## 复用候选

优先复用 Docling NativePdfPipeline 的原生文本、图片、页处理与来源结构。该路径不恢复复杂阅读顺序、标题和表格；相应能力由外部文档分析增强，不能照搬默认本地模型管线。底层 PDF 库作为上游依赖或必要补充。 依据见 [横向选型](../../../../docs/research/2026-10-15-module-selection.md) 与 [实现方案](../../../../docs/implementation-plan.md)，已在 Python 3.12 环境锁定并验证所选路径；不代表所有 Office 特性或复杂 PDF 均被完整恢复。

## 实现前验收

混合扫描/文字页、多列、旋转、表格、损坏/加密、空页；P0 原生路径与 P1 模型增强分开验收。

共同规则见 [处理流程](../../../../docs/pipelines.md) 与 [评测计划](../../../../evals/README.md)。
