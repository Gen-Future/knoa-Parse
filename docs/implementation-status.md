# 实施记录：原生文档接入

日期：2026-10-15。Clash 代理已解决此前依赖下载阻塞；本轮完成 M0 的技术验证和 M2 的初始原生路径。原始第一批记录保存在 [初始基线](../evals/baselines/2026-10-15-initial.json)，本轮依据见 [文档基线](../evals/baselines/2026-10-15-documents.json)。

## 当前可运行能力

- UTF-8 TXT / JSON：保留原文、字符位置和数据类型，继续拒绝重复键/非有限值及资源越界。
- DOCX：复用 Docling 原生 backend / SimplePipeline，保留正文、重复段落、列表、表格、图片和可获取的页眉等；定位到完整上游树，不冒充 Word 页码或原 XML 节点。
- PPTX：保留原生文本、表格、图片和演讲备注的角色/幻灯片关联；当前不输出原始 shape ID 或精确形状定位。上游 EMU 坐标保留在原始产物，不当作 PDF 点数。
- XLSX：复用 Docling 的区域组织；补充原始单元格、A1、公式、缓存、类型、数字格式、合并与隐藏状态。无缓存的公式及区域外公式单元格独立保留，不填 0、不计算公式。数组/数据表公式当前明确拒绝。
- PDF：原生文本单元、位图和页/区域。只读原生编码内容，不重建阅读顺序、版面、标题或表格；图片型页面明确报告文字覆盖缺口，保留图片并返回 partial。无原生内容不被解释成“视觉空页”。

六种后缀共享 API/CLI、SQLite 任务、租约、受控子进程及统一结果。Office/PDF 只有在可选 documents 组审计通过时才出现在运行能力接口。未安装文档组，文本/JSON 与 API 仍可独立工作。

## 依赖与执行边界

已使用 Python 3.12.11 创建仓库专属 .venv，生成完整 uv.lock。锁包含跨平台/跨 Python 版本的 66 条包记录；本机完整 API/文档/开发环境安装 61 个唯一分发。锁及所选安装依赖均不包含禁止的本地推理或模型下载组件。

文档组只采用 docling-slim 2.139.0 的指定原生 extras；显式关闭模型增强、远端调用、外部插件及 PDF 全页渲染，解析线程限制为 2。没有引入上游 UI、Serve、RAG 存储、Word/Excel 计算引擎或本地 OCR/ASR。

模型缓存为空的新进程实验完成四种转换，没有加载 Torch/Transformers/ONNX 等推理模块。审计拦截到两次 Python 平台信息探测（uname -p 与对当前解释器执行 file -b），均未放行，转换仍成功。没有未解释的网络/进程尝试。这里的 Python 审计不是完整 OS 沙箱。

依赖分组拆卸实验也通过：去掉 documents 后，基础/API/开发环境仍可启动并通过对应回归，只显示文本/JSON；随后从本地缓存恢复完整文档组。大小为该机器的环境逻辑文件字节，含开发依赖，不能当作通用安装大小或纯运行时大小。

## 结果、定位与产物

继续使用 0.2.0-draft.1 的既有 Source/Artifact/Block/定位结构；本轮没有改变顶层契约或主仓快照。格式细节放在既有 data 字段，并补充语义说明。完整 Docling JSON 及图片作为可读取 artifact 保存，派生树指针逐一验证可解析。

子进程只写任务暂存目录。父进程核对来源绑定、每个派生产物的摘要/大小及总输出预算，再随成功租约事务注册；取消/超时后清理暂存文件。CLI 对 partial 仍返回可用结果，退出码为 3；不会隐藏图片型 PDF 的已保留证据。
