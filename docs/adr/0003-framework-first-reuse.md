# ADR 0003：优先复用成熟解析项目的能力模块

> 历史决策：关于 RAG-Anything 必须抽取接入及双主线的安排已由 [ADR 0004](0004-selective-module-integration.md) 替代。保留此文记录通用复用原则；当前实施以新决策和实现方案为准。

- 日期：2026-10-15
- 状态：采用的设计方向；具体代码和版本等待集成实验验证
- 背景：原方案把复用重点放在底层文件库，未充分利用成熟项目在结构恢复、内容组织和多模态流程上的积累。
- 替代范围：替代 ADR 0002 的开源复用策略，保留资料家族、外部模型、证据契约和仓库边界。

## 决策

1. 以 Docling、RAG-Anything 等成熟项目的能力模块为优先研究和采用对象。允许依赖调用、抽取并改造代码、借鉴设计与算法；不预先排除其中任何方式。
2. 优先复用能独立维护的一段完整能力，包括输入输出、处理逻辑和行为测试；不以零散复制函数或重写底层库作为默认路径。
3. Docling 是文档转换的首要集成实验对象。RAG-Anything 是上下文组织、多模态增强与音画对齐的首要代码借鉴对象。两者不承担完全相同的职责，也不代表已经可以无改动接入。
4. 不引入上游本地模型推理和权重下载。模型步骤通过 core 的外部 Provider 接口替换；如果非模型逻辑与本地模型无法经济地拆开，该模块暂不采用。
5. 底层库继续作为上游依赖、必要工具和明确缺口的补充。不得仅因其历史较长就否定它，也不得用挑选底层库代替研究成熟项目。
6. 资料家族负责流程与能力选择；engines 封装成熟文档转换实现；enrichment 组织按内容类型的上下文与增强逻辑；processors 保留底层非模型工具；providers 接入外部模型。
7. 对外只提供 Knoa Parse 的安装、配置、任务、错误与版本化结果接口。默认部署不要求用户分别启动 Docling、RAG-Anything 或 LightRAG，不把上游参数原样暴露成公共 API。
8. 优先在单一后端语言中复用。Python 是本次集成实验的推荐语言，是否锁定由实验结果决定。原生扩展或受控媒体命令不等于维护多个业务项目；不为一个可选功能默认引入另一套服务及运行时。

## 复用方式选择

| 方式 | 适用条件 | 维护方式 |
| --- | --- | --- |
| 依赖 + 内部适配器 | 公开入口稳定、可关闭本地模型、依赖可接受 | 固定发布版本或提交，维护映射与契约测试；Docling 优先尝试此方式 |
| 抽取源码并改造 | 有价值的模块被不需要的项目能力耦合，分离范围可控 | 保留许可及来源，连同相关测试迁移，记录修改差异；RAG-Anything 部分模块优先尝试 |
| 借鉴设计重新实现 | 算法简单清晰，但抽取的依赖与维护负担大于收益 | 记录借鉴依据、行为要求和与上游的差异；不能把改名后的复制称为独立实现 |

若直接依赖不可行，先评估最小补丁或可维护的源码抽取，再决定是否重新实现；不自动退回一套从零拼装的解析器。维护整项目 fork 是最后的专项决策，不是初始化要求。

## 采用门槛

- 核对固定版本的实际依赖、导入路径和运行路径；离线且模型缓存为空时，非模型功能仍能运行，模型功能明确报外部能力缺失。
- 使用同一批资料对比上游输出与适配输出，核对结构、顺序、来源和错误；适配损失必须可解释，不能用统一 Markdown 掩盖。
- 抽取代码时记录仓库、固定提交、原路径、许可证、文件摘要、修改理由和测试来源；保留要求的版权及 NOTICE。当前研究记录的 blob SHA 不替代采用时的提交锁定。
- 分别验证代码复用和外部模型替换后的效果。原项目的基准成绩不自动适用于 Knoa Parse。
