# ADR 0002：按资料类型组织流程，模型能力通过外部服务接入

- 日期：2026-10-14
- 状态：本轮结构基线；具体库与服务供应商仍为候选
- 依据：用户要求先按视频、PDF、文本、PPT、Excel 等资料类型划分项目，并复用成熟开源能力；不采用本地机器学习模型实现 OCR、ASR、大模型等能力。

## 决策

1. `src/knoa_parse/parsers` 按 13 个资料家族划分，每类拥有独立处理流程、选项与验收样例。扩展名是家族内的格式差异，不是新建服务的理由。
2. `src/knoa_parse/processors` 封装非模型工具，如解封装、抽音轨、抽帧、渲染、Office 转换、标记解析与受限解包。
3. `src/knoa_parse/providers` 按 OCR、ASR、视觉理解、文档分析、文本模型能力隔离外部服务适配。接口定义归 core；流程不直接依赖供应商 SDK。
4. 本仓不引入本地模型权重、推理框架、模型下载器、GPU 推理镜像或隐式模型回退。包括本地版面识别、表格识别、VAD、说话人识别和基于模型的 MIME 检测，不只排除 LLM。
5. 外部服务不可用时明确失败或产生标记完整性缺口的部分结果；不得自动安装本地模型补救。
6. 以结构化内容与来源定位为内部产物，Markdown 是输出视图。文档、表格、音视频无需强行变为同一种纯文本处理流程。

## 可共享的部分

视频与文本的专用流程彼此独立，但仍共享任务、来源标识、错误、资源预算和证据规则。视频产生的音轨、PPT 内嵌图片、邮件附件由 core 的子任务分派接口转交对应家族；禁止解析器直接导入另一个家族的内部实现。

本期不拆更多仓库，不创建 13 个微服务，不安装所有候选依赖。目录和文档的存在不代表格式已支持。

## 开源复用策略

本节于 2026-10-15 经 ADR 0003 调整，当前以 [ADR 0004](0004-selective-module-integration.md) 为准：按证据选择成熟模块，允许直接调用、合理源码复用和设计借鉴，不预设用户举出的项目必须接入。采用范围仍需验证不会引入本地模型；外部托管文档服务由 DocumentAnalysisProvider 适配。

来源与候选比较见 [调研](../research/2026-10-14-parser-landscape.md)。无具体版本锁定、样例验证和依赖检查之前，不宣布任何候选成为正式选型。

## 输出契约的影响

现有 `0.1.0-draft.1` 仅覆盖文本、页码、时间定位，无法完整承载工作表单元格、幻灯片形状、附件层级等信息。本轮保留它及主仓快照不变，另写 [下一版设计](../result-model.md)。多格式实现必须先发布相应新草案并升级消费端；不能偷偷往旧版本塞字段。
