# ADR 0004：按证据选择模块，限定运行时与源码接入范围

- 日期：2026-10-15
- 状态：采用的方案决策，生产启用仍需集成验收
- 替代：ADR 0003 中预设 Docling 与 RAG-Anything 为两条主线的安排，以及必须迁移上下文/视频源码的任务。
- 保留：资料类型隔离、成熟模块优先、允许合理源码复用、禁止本地模型、统一证据与独立仓库边界。

## 决策

1. 用职责匹配、模型边界、可分离性、发布/回归证据和总维护成本选择模块。用户举出的项目不视为必须采用。
2. 默认只保留一个通用文档引擎：Docling 的精简非模型格式路径；采用发布版本作为实验基线。Excel 的原始单元格语义以有限补充层保留。
3. 场景检测在视频阶段直接采用 PySceneDetect 的专门算法；FFmpeg/ffprobe 负责媒体基础操作。Trafilatura 只在正文提取目标明确时按需加入。
4. RAG-Anything 当前仅设计参考，不安装、不预设源码搬运。它的有限上下文逻辑与 Knoa 引用契约差异较大，视频底层能力可直接复用专门项目。
5. 当前不安装 Unstructured、MarkItDown、MinerU、Marker、Kreuzberg/Xberg、DocVortex、Tika 全包。拒绝理由按模块与当前版本记录，不永久否定这些项目。
6. 第三方类型止于内部适配层；所有入口共享任务、配置、错误和结果。外部模型由独立 Provider 调用，不把自建模型服务包装成“外部接入”。
7. 不提前建设 vendor 树、大框架 fork、插件市场、微服务网格或第二套状态系统。允许正常依赖中惰性的普通源码，重点排除不需要的安装依赖和执行路径。
8. 每次增加依赖或复制源码都要说明唯一用途、替代/复用现有能力的可能性、来源许可、依赖闭包、回归和退出方式。无独特收益时不新增。

完整证据与候选矩阵见 [横向调查](../research/2026-10-15-module-selection.md)；实施与准入标准以 [实现方案](../implementation-plan.md) 为准。
