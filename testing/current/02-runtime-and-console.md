# 任务、接口与工作台

前置：隔离数据目录；除停止/恢复类用例外，API 与独立 worker 均运行。接口位于 console 的 `/api/v1`，独立 API 为 `/v1`。任务 ID、Source ID 和原始响应是核心证据；UI 截图辅助。

## 任务与预算

- [ ] **RUN-01 / P0 / 完整链路**。上传带中文名和 emoji 的 TXT，提交任务，等待、看内容并下载原件/结果；再由 CLI 创建另一任务。预期：两种入口在同一实例可见、内容和来源正确，无需工作台登录。原始上传与创建任务是两步，记录对应 ID。
- [ ] **RUN-02 / P0 / 无 worker 排队**。停止隔离 worker 后上传 2 个文件并提交，等两次刷新，再启动 worker。预期：停止时保持 queued、不凭空完成；启动后得到真实结果；浏览器请求不是解析执行器。记录停启时间与状态变化，不靠 UI 延迟推断 worker 心跳。
- [ ] **RUN-03 / P0 / queued 取消**。worker 停止时取消排队任务，随后启动 worker。预期：任务保持 cancelled，不再被执行或产生可误取的成功结果；取消不影响其他排队任务。重复取消应有一致可解释响应，不产生第二个任务。
- [ ] **RUN-04 / P0 / running 取消与超时**。准备接近上限的合法样本或隔离慢解析器，确认 running 后取消；另一次让它超过当前 30 秒限制。预期：当前解析子进程实际退出，状态为取消/超时失败、暂存产物不冒充已发布；后续小 TXT 正常处理。仅看到 UI 状态变化不算通过，需进程及目录证据。无法稳定得到 running 场景记阻塞。
- [ ] **RUN-05 / P1 / 重启与中断**。queued 时重启 API、正常关闭 worker 再启动；另做 worker 强制终止。预期：已完成任务与原件仍可取，queued 不丢；强制中断后记录租约/任务的实际可恢复性，不预设逐单元恢复已实现。遗留 running、重复执行和人工恢复条件进入 UNC-06，不得静默重建数据库。
- [ ] **RUN-06 / P0 / 幂等与重试**。API 对同一 source_id/target 使用同一 idempotency_key 连续提交两次，再用同一 key 改 source_id；另一次不带 key 提交。预期：相同请求不会变成重复任务；冲突明确拒绝，不返回错误来源结果。无 key 的重复提交不要求自动去重。当前 target 仅 native_extract，不虚构其他可用选项。保存四次响应和任务数量。
- [ ] **RUN-07 / P1 / 接入检测**。逐一上传错后缀 PDF、伪装 Office 的普通 ZIP、损坏 Office、零字节和未支持后缀。预期：格式冲突或不支持明确拒绝/失败，不单凭后缀路由，也不把 archive 规划能力当支持。分别记录 HTTP 和任务阶段，不能要求所有坏文件在同一阶段失败。
- [ ] **RUN-08 / P0 / 资源边界**。在隔离环境分别验证上传 10 MiB 临界与超限、派生总输出超过 20 MiB、PDF 超过 100 页、JSON 超节点预算。预期：上限内的合法资料按能力处理，超限有明确 resource_limit 类错误、有界结束；失败后小文件仍能解析。构造不上输出上限时标阻塞，不能拿大输入被拒代替大输出验证。
- [ ] **RUN-09 / P1 / API 错误可解释**。访问不存在 job/source/artifact，读取尚未完成任务的 result；jobs limit 分别用 0、1、100、101。预期：不存在/未就绪有明确响应，无栈或磁盘路径泄露；limit 1/100 有效，0/101 拒绝；查询不领取或改变任务。证据：响应和前后状态。
- [ ] **RUN-10 / P1 / CLI 一致性**。分别 CLI 解析完整 TXT、混合 PDF、损坏资料，检查 PowerShell `$LASTEXITCODE` 与 stdout/stderr。预期：完整 0、partial 3、失败 2；中文/emoji 不因终端默认编码破坏；结果证据与 API 同语义，错误文本不混入成功 JSON。

## 工作台真实性与使用体验

- [ ] **UI-01 / P1 / 首次进入与断连**。直接打开页面并刷新，临时停止 API、恢复后点击重连。预期：Demo 不弹登录、不要求旧 token；断连明显可见，旧数据不冒充最新；恢复后可继续操作，不把连接失败称作解析失败。
- [ ] **UI-02 / P0 / 状态与统计**。准备 queued/running/succeeded/partial/failed/cancelled；用现有长任务模拟 running。预期：状态筛选与详情一致，partial 不计为完整成功；不显示虚构百分比、心跳、费用或耗时。能力仅显示当前实际启用格式。
- [ ] **UI-03 / P1 / 列表范围与查找**。创建超过 100 个小合成任务，用中文名、ID 搜索，再输入完整旧任务 ID 打开早期任务。预期：最近列表统计范围明确，has_more 不冒充全库总量；列表内搜索正确，旧 ID 可直达。相同文件名仍能通过 ID 区分。
- [ ] **UI-04 / P1 / 上传和不确定响应**。批量上传正常/损坏混合文件，另提交超过 UI 的 20 文件批次；上传期间中断连接。预期：逐份状态可辨，不因一份失败伪装全成；批次限制有说明；请求结果未知时不自动重放 POST，不制造重复任务，已取得 source ID 可帮助追查。
- [ ] **UI-05 / P0 / 内容与完整下载**。检查长正文、合并表格、原生图表、公式、图片、定位、coverage 和 issues 各一例。预期：预览与完整 JSON 语义一致，截断有提示；下载是完整内容，0/false/null 不混淆；原始树/图片/原件均可下载，partial 的产物仍可用。
- [ ] **UI-06 / P0 / 文件内容不执行**。用包含 `<script>`、`<img onerror=...>` 和公式样式字符串的 TXT/JSON/文件名，以及 SVG/HTML 内容样本。预期：前述文本转义显示，不运行脚本、公式或导航；不支持图片类型不强行嵌入执行。记录屏幕与控制台异常，不使用真实破坏脚本。
- [ ] **UI-07 / P1 / 轮询与选中稳定性**。选择已完成长文并滚动，在另一窗口提交任务；切后台再返回并切换不同任务。预期：更新列表不频繁抢焦点/重置证据滚动，任务详情不串绑；后台不持续高频请求，恢复后刷新真实状态。通过浏览器网络面板核对，不能只靠肉眼判断。
- [ ] **UI-08 / P1 / 响应式与键盘**。在 320、390、1440 CSS 像素宽度和 200% 缩放下逐项操作上传、筛选、详情和模型设置；只用 Tab/Shift+Tab/Enter、结果标签方向键、Ctrl/Meta+K。预期：无阻断性横向溢出/遮挡，焦点可见、按钮能触达，信息不只靠颜色；减少动态效果设置可用。截图与键盘问题逐项记录。
- [ ] **UI-09 / P1 / 前端可拆卸**。停止 console，用独立 API factory 和 CLI/worker 处理 TXT；在无 documents 环境查看能力和解析 TXT/JSON。预期：不需要前端、Node/npm 或文档组即可工作；只声明实际可用后缀，不因 UI 缺席影响解析。不要卸载当前主环境，使用独立虚拟环境。
