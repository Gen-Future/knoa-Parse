# 本轮目标与验收准备

这是已有实现的补建测试需求，日期 2026-10-19；当前所有人工勾选项初始均为未执行。后续工程按目录约定真正前置定义。

## 开发目标与边界

目标：可靠接入六种原生资料，保留可核对内容、位置和原件；任务失败或覆盖不足如实报告；工作台只观察和操作原有 API；模型入口独立、配置不泄露密钥。不能以“没有报错”“界面好看”“状态绿色”代替内容验收。

本轮不要求 OCR/ASR/视频、复杂 PDF 表格/阅读顺序、Word 页码、PPT 原始 shape 精确定位、公式计算、多租户、生产部署和主仓新契约消费。它们不得被 UI 宣称已支持。

P0：证据错误、漏报缺口、密钥泄露、数据串绑、取消失效、原生解析隐式联网等阻断问题。P1：常见资料、任务与关键操作正确性。P2：复杂场景探索、可用性和性能观察。P0/P1 失败不能以自动测试通过豁免；已知未支持能力不直接等于实现回归，但静默给出错误证据须按缺陷处理。

## 环境准备

1. 记录分支、HEAD、未提交改动、Windows/浏览器版本、解释器、依赖组和测试时间。当前有未提交实现，只有 HEAD 无法唯一标识版本，需同时保留变更摘要或补丁。
2. 从仓库根运行；Windows 用 `.\.venv\Scripts\python.exe`。新建隔离目录 `.local/manual-testing/2026-10-19/`，通过独立终端的 `KNOA_PARSE_DATA_DIR` 指向其 data 子目录。API/console 与 worker 两个终端必须使用同一路径。
3. 可在独立端口 8766 启动 console，避免扰动现有 8765 实例：`python -m uvicorn knoa_parse.apps.console:create_from_env --factory --host 127.0.0.1 --port 8766`；这里的 python 应替换成仓库解释器。另一个终端用相同解释器运行 `-m knoa_parse worker`。不要同时让两个服务占同一端口。
4. 模型测试用独立的 `KNOA_PARSE_PROVIDER_CONFIG` 文件；修改配置、断网、终止进程只针对隔离实例。计费调用仅在专门模型用例中人工发起，其他用例使用未配置或合成 Provider。不要复制真实 key 到执行记录。
5. 准备原件阅读器：文本编辑器、JSON 查看器、Word/PPT/Excel 或兼容软件、PDF 阅读器。记录不同阅读器的显示差异；测试原件与解析输入的 SHA256 应一致。
6. 结果均下载完整 JSON 和相关产物。UI 有预览截断时，改用完整结果对照，不能把预览少行直接认定为解析丢失。

## 最小样本集

| 家族 | 必备资料 | 人工预标内容 |
| --- | --- | --- |
| TXT | UTF-8 中文/emoji/BOM/CRLF、重复段落、非法编码 | 首尾句、空行、重复次数、字符片段 |
| JSON | 嵌套对象/数组、特殊键、类型、重复键 | 指针、值和类型，不仅显示字符串 |
| DOCX | 至少 3 份不同来源中文文件；含标题/列表/合并表/图片/备注性内容 | 正文段落、表格跨度、页眉页脚、脚注、图片数 |
| PPTX | 至少 3 份；正文/分组/备注/表格/原生图表 | 幻灯片归属、重复文字、系列类别/数值 |
| XLSX | 至少 3 份；多表/隐藏/公式/空表/特殊类型 | sheet/A1、原始值、公式、缓存、合并范围 |
| PDF | 至少 4 份；原生中文、多列旋转、纯扫描、混合文字图片 | 页码、目标文本区域、图片页、原生文字范围 |
| 异常 | 截断/损坏/错后缀、零字节、超过预算 | 预期拒绝阶段、已有内容是否应保留 |

可先运行 `scripts/evaluate_m2.py` 得到 15 个合成样例与结果，再加入上表真实文件。合成样例通过不能替代真实资料验收。真实样本数量只是起步门槛，不构成准确率统计。

## 统一执行与结论

每条记录：用例 ID、样本 SHA、步骤、实际状态、原件对照、关键 JSON 位置、截图/日志、结论和问题编号。语义预期在运行前写好。模型异常、预算边界、进程中断可能需要命令行或隔离模拟服务；没有工具条件记阻塞。

本轮接受条件：适用 P0/P1 全部执行并通过；真实最小样本逐份核对关键内容与位置；未支持特性不伪装成功；不确定项有明确处置、负责人或后续任务。P2 不能默认为通过，也不能因延期而宣称全面验收完成。
