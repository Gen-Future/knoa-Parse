# 开发前测试需求：Knoa Parse 工作台 V2

状态：待实现；创建日期：2026-11-05；关联工程/需求：桌面优先的证据调试界面；负责人：Knoa Parse。

## 目标与范围

将 `apps/console` 升级为同时服务开发调试和日常使用的本地工作台。前端继续使用随 wheel 发布的静态 HTML/CSS/ES modules，只消费现有 HTTP API，不修改解析层、Provider、worker、公共结果契约、任务状态语义或模型密钥存储边界。

视觉目标是暖白、深松绿、墨色正文、低噪声边框和充足留白；主要验收桌面 1440、1280、1024 宽度。窄屏只保持既有基本可用，不新增移动端完整调试目标。

本阶段包含：

- 解析工作台、能力清单、模型服务三个主视图；
- 任务列表、上传、证据 Inspector、coverage/issues/artifacts 浏览；
- Inspector 内诊断抽屉，展示任务事实、证据链、快捷操作和最近 100 条前端同步事件；
- 设计令牌、空/加载/错误/部分完成状态、键盘焦点和 tab/tabpanel 语义；
- 开发前后测试文档和 1440/1280/1024 人工验收记录。

本阶段不包含：新的后端诊断 API、worker 阶段事件、真实费用/耗时/心跳、Provider 账目查询、跨进程恢复、生产鉴权、移动端完整重排或任何本地模型能力。

## 不允许妥协的边界

- 不增加 Node/npm、CDN、外部字体、前端运行时或新的 Python 分发依赖。
- 不在浏览器持久化 API Key；调试事件不得记录密钥、原始请求体或外部服务凭据。
- 所有资料内容、文件名、原始结果、SVG/HTML/公式均按不可信文本处理，不能直接执行。
- 不把前端轮询、估算百分比、客户端耗时或空值包装成后端阶段、费用、心跳或成功状态。
- 删除 `apps/console/static` 后，独立 API、CLI、worker 仍应可启动。

## 样本与独立预期

使用合成任务和现有测试 fixture，不提交真实资料、密钥、运行数据库或截图原件。至少准备以下状态样本：

- 六种任务状态：`queued`、`running`、`succeeded`、`partial`、`failed`、`cancelled`；
- 有结果、无结果、来源缺失、结果 artifact 缺失、空 blocks、空 issues、空 coverage；
- 含表格合并、图片、定位、长文本、公式/缓存和多 artifact 的结果；
- 恶意 HTML/SVG/脚本字符串、超长文件名、超长任务 ID、超长 JSON 和空字段；
- capability 返回多个格式、无外部模型、外部模型已配置和环境变量只读；
- 连接失败、刷新失败、上传失败、取消竞态、模型保存失败和测试连接失败。

独立预期来自 API 响应、结果契约和本需求，不从待测页面输出反推正确答案。人工截图只保存脱敏布局证据，完整结果仍通过 API/artifact 下载核对。

## 验收用例

- [ ] ID：CONSOLE-V2-01；优先级：P0；目标：桌面三种尺寸保持稳定层级。
  - 前置条件/样本：本地 console 服务和合成任务；视口 1440×900、1280×800、1024×768。
  - 操作：打开工作台，依次切换三个主视图，选择任务并展开 Inspector/诊断抽屉。
  - 预期：固定侧栏、顶部状态、上传区、任务列表和 Inspector 层级清晰；无横向溢出、内容遮挡或滚动层失控。
  - 证据：三种尺寸截图、浏览器控制台无错误。
  - 验证方式：人工；环境：Windows 浏览器；对应测试：阶段验收记录。

- [ ] ID：CONSOLE-V2-02；优先级：P0；目标：六种任务状态显示真实且可区分。
  - 前置条件/样本：六种状态任务。
  - 操作：筛选全部、处理中、需关注，逐个选择任务。
  - 预期：状态文字与颜色同时表达；`partial`/`failed` 不显示为成功；queued/running 只显示后端提供的状态，不虚构百分比。
  - 证据：任务列表和 Inspector 截图、状态响应 JSON。
  - 验证方式：自动+人工；对应测试：`tests/console_model.test.mjs`、浏览器记录。

- [ ] ID：CONSOLE-V2-03；优先级：P0；目标：上传与任务定位闭环可用。
  - 前置条件/样本：一个已启用格式、一个不支持格式、多个文件。
  - 操作：拖放、文件选择、输入完整任务 ID、搜索名称和 ID。
  - 预期：按 capabilities 校验格式；上传失败有明确原因；成功后自动刷新并选中任务；搜索只作用于已返回窗口；完整 ID 可打开窗口外任务。
  - 证据：上传响应、任务 ID、失败提示和截图。
  - 验证方式：自动+人工；对应测试：现有 console/API 测试及新增交互记录。

- [ ] ID：CONSOLE-V2-04；优先级：P0；目标：证据 Inspector 保持来源可追溯。
  - 前置条件/样本：含 text/table/image、locator、coverage、issues 和 source/engine_result/derived artifact 的结果。
  - 操作：切换内容、覆盖与问题、原始结果 tab；展开诊断抽屉；下载原件、完整结果和 artifact。
  - 预期：来源、定位、覆盖、问题和产物关系与 API 一致；显示截断只影响预览；下载内容完整；缺失 artifact 明确显示不可用。
  - 证据：页面截图、下载文件 SHA256、API 结果 JSON。
  - 验证方式：自动+人工；对应测试：新增 Inspector 纯函数测试和浏览器记录。

- [ ] ID：CONSOLE-V2-05；优先级：P0；目标：诊断抽屉只记录前端真实事件。
  - 前置条件/样本：连接成功、刷新、加载来源/结果、上传、取消、请求错误和重连流程。
  - 操作：执行上述动作，展开诊断抽屉并滚动到最早事件。
  - 预期：最多保留最近 100 条；按时间倒序或明确顺序显示；不含 API Key、原始请求体、服务器路径或完整资料内容；刷新页面后清空；事件不改变任务状态。
  - 证据：事件列表截图和脱敏 DOM 检查。
  - 验证方式：自动+人工；对应测试：新增诊断事件纯函数测试。

- [ ] ID：CONSOLE-V2-06；优先级：P0；目标：连接、刷新、上传、取消和结果错误可解释。
  - 前置条件/样本：服务停止、API 500/409/413、来源缺失、结果未发布、取消竞态。
  - 操作：分别触发错误并重试连接/刷新。
  - 预期：全局错误、局部错误、空状态和 toast 有清晰职责；不会吞掉错误，也不会自动重试创建任务；重连后旧会话响应不会覆盖新状态。
  - 证据：错误响应、截图、事件记录。
  - 验证方式：自动+人工；对应测试：现有 console 测试和新增状态测试。

- [ ] ID：CONSOLE-V2-07；优先级：P1；目标：模型服务密钥边界不被前端破坏。
  - 前置条件/样本：已配置密钥、未配置密钥、环境变量覆盖、保存失败和连接测试失败。
  - 操作：读取、修改、保存、重新读取和测试模型设置。
  - 预期：密钥只显示“已配置/未配置”；留空保留原密钥；更换渠道要求新密钥；环境变量覆盖时只读；诊断、localStorage、页面源码和错误消息不出现密钥。
  - 证据：网络请求摘要、页面截图、浏览器存储检查。
  - 验证方式：自动+人工；对应测试：现有模型设置测试和浏览器记录。

- [ ] ID：CONSOLE-V2-08；优先级：P1；目标：键盘与辅助技术语义完整。

  - 证据：Accessibility Tree 截图或检查记录、键盘操作视频/日志。
  - 验证方式：人工+静态检查；对应测试：浏览器验收记录。

- [ ] ID：CONSOLE-V2-09；优先级：P1；目标：不可信内容安全显示。

  - 操作：上传并打开结果/原始结果/图片预览。
  - 预期：内容只作为转义文本显示；图片只通过已授权 artifact URL 加载；不执行脚本、HTML、SVG 或公式；控制台无注入副作用。

  - 预期：UI 截断有明确提示；长文本可滚动或折叠；完整内容可下载；空字段显示未知/无数据；不出现 `undefined`、溢出或脚本错误。
  - 证据：三种桌面尺寸截图和下载文件核对。

## 通过门槛与回归

- P0 用例必须全部通过；任一任务状态、证据完整性、安全边界或解析隔离失败，V2 不得交付。
- P1 用例允许在 after 文档中列出环境阻塞，但不得把未执行或不确定项标为通过。
- 自动验证至少包括 `node --check`、`node --test tests/console_model.test.mjs`、`.venv\\Scripts\\python.exe -m unittest tests.test_console`、完整 Python 回归、`scripts/check.py`、依赖审计和 `git diff --check`。
- 视觉验收以 1440/1280/1024 为准；没有横向溢出、内容遮挡、状态误报和密钥泄漏才算通过。
- 前端提交必须使用中文说明；每个阶段完成后独立提交并尝试推送 `origin/main`。
