# 开发前测试需求：M4-A 音视频媒体探测边界

创建日期：2026-11-04；状态：实现前定义。范围：以受控外部 `ffprobe` 进程建立音频/视频/字幕流探测、时间基、VFR 帧 PTS 和源身份校验边界；不实现转码、ASR、OCR、视觉模型、场景检测或产品路由。

## 目标与边界

- `core/media.py` 只定义与引擎无关的源身份、流、时间基、帧 PTS 和探测结果模型；路径字段只存在于受信任的进程边界，序列化结果不得泄露路径。
- `processors/media/ffprobe.py` 使用参数数组、`shell=False`、固定 JSON 输出和无 stderr 回传；二进制缺失、超时、非零退出和非法 JSON 都归一化为稳定错误。
- 探测前后重新计算源 SHA-256/大小，源变化、路径不可用、软链接输入或摘要不匹配不得继续。
- 音频、视频、字幕保留 stream index、codec、time base、PTS 相关字段、持续时间和必要的几何/采样信息；数据/附件流不制造虚假 time base。
- 可选帧扫描必须保留实际 `best_effort_timestamp` 与 time base 换算的毫秒值，不能用帧号除固定 FPS 替代 VFR 时间；所有输出受流数、帧数和字节上限约束。
- 这是基础探测能力，不声明任何格式已开放，不执行媒体解码、不写 ParseResult、不把本机安装 FFmpeg 当作验收。

## 验收用例

- [ ] M4A-01 / P0：有效音视频流映射 format、stream index、codec、time base、duration、尺寸、采样率和帧率；负 start time 可保留。
- [ ] M4A-02 / P0：VFR 帧实际 PTS 与 time base 转为毫秒；负 PTS 可保留；不根据 FPS 推算或排序覆盖原始值。
- [ ] M4A-03 / P0：音频缺失、视频缺失、字幕存在、数据/附件流存在时结果明确；非媒体流不虚构时间基。
- [ ] M4A-04 / P0：源摘要/大小不符、源变化、不可用路径和软链接在外部进程前或后安全失败。
- [ ] M4A-05 / P0：ffprobe 缺失、超时、非零退出、超出输出/流/帧预算、重复 JSON 键、非法 time base/几何/PTS 均稳定失败且不暴露 stderr。
- [ ] M4A-06 / P0：命令使用参数数组、禁止 shell/重定向；配置超时和边界严格校验。
- [ ] M4A-07 / P0：专项测试、完整回归、静态检查、依赖审计和文档检查通过；依赖增量为 0。

FFmpeg/ffprobe 的实际版本、许可证构建选项、跨平台安装包、真实 VFR/损坏/长文件验收、转码、分段、ASR 和场景检测留在后续 M4 阶段。
