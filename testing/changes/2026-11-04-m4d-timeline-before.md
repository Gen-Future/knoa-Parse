# 开发前测试需求：M4-D 音频分段与字幕时间线

创建日期：2026-11-04；状态：实现前定义。范围：在已探测的音轨时间线上规划受服务上限约束的重叠音频片段，并解析 SRT/WebVTT 为原时间线字幕 cue；不实现转码、ASR 调用、字幕 OCR、说话人推断或产品路由。

## 目标与边界

- 音频片段的 `core` 区间必须无缝覆盖有限媒体时长；请求区间可在前后增加重叠，但每个请求不得超过 `max_segment_ms`，返回结果必须以后续 core 区间去重。
- 无音轨、无有限 duration、错误 stream、非法上限和过大重叠显式失败；不把视频时长或空转录当成音轨存在。
- SRT 使用逗号毫秒，WebVTT 使用点毫秒并要求 `WEBVTT` 头；保留多行文字、顺序和原始 cue 独立 ID，非法 header/timestamp/range/cue 不静默跳过。
- 所有时间为原媒体毫秒左闭右开；解析阶段不做字幕与 ASR 去重，不把字幕当作 ASR 结果，不写 ParseResult。

## 验收用例

- [ ] M4D-01 / P0：4 秒服务上限、500ms 重叠时 core 区间连续覆盖，request 区间包含边界上下文且不超过上限。
- [ ] M4D-02 / P0：最后不足一个窗口的片段正确收口；duration 缺失、无音轨、错误 stream、非法 overlap/max 统一稳定失败。
- [ ] M4D-03 / P0：SRT/WebVTT 时间正确转为毫秒，多行字幕保留，VTT cue settings 不污染结束时间。
- [ ] M4D-04 / P0：字幕头、timestamp、空文本、反向范围和乱序 cue 拒绝；不自动重排或删除坏 cue。
- [ ] M4D-05 / P0：专项、静态检查、依赖审计和文档检查通过；不新增模型/解码依赖。

真实字幕容器抽取、字幕编码、音频转码、ASR 边界去重、无声/静音检测和跨轨校准留在后续 M4 产品阶段。
