## 发现并修复的行为

1. 原生图表的数据本已位于 Docling `meta.tabular_chart.chart_data`，适配层却只寻找图片字节。本轮把该结构映射为 `table`，`data.role=native_chart`，保留类别、系列、数值、行列跨度和原生图表类型。图表不再被误报为丢失的图片。
2. 图表表格定位到保留的上游节点，精度为 derived_exact；不是原工作表单元格，因此不为它构造 A1。普通 Excel 原始单元格和真实区域仍保持 sheet_range。
3. 图表未渲染时返回 `chart_visual_not_rendered` warning。只保留原生数值，不声称获得视觉理解，也不增加渲染器、模型或第二套图表解析算法。
4. 原生页眉曾使含扫描正文的 PDF 返回 completed。本轮规定：含位图页面的覆盖保守记 failed，并给出 `external_ocr_required` error；存在原生文本或图片产物时结果为 partial。该策略会使含装饰图片的 PDF 也返回 partial，当前不猜测图片是否包含正文。

## 如何复现

完整环境执行 `python scripts/evaluate_m2.py`；Windows 使用 `.\.venv\Scripts\python.exe scripts/evaluate_m2.py`。报告在 `.local/m2-acceptance/report.json`，原件、任务、上游树和派生图片保留在同目录下，方便检查失败证据。CLI 任一所选样例失败或被依赖阻塞时退出码为 1。

不安装 documents 时，完整模式明确报告文档样例 blocked；`--base-only` 显式只执行 4 个文本/JSON 样例。报告含 scope，不能把基础组通过理解为六格式通过。

所有可用结果都核对 artifact 摘要/大小、TextSpan 原文、JSON 类型、派生 JSON Pointer、原始单元格位置、PDF 页尺寸/区域、图片产物及指定内容/状态。评估器还有负例回归：完成状态下丢正文、位置越界、false 变 0 和未知检查项均不能通过。

Windows 运行结果见 [M2 基线](baselines/2026-10-19-m2.json)。依赖锁未变，没有新增运行时依赖或修改顶层契约，主仓旧契约快照保持不变。
